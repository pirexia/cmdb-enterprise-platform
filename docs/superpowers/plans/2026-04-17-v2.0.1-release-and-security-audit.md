# v2.0.1 Release & Security Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump the platform to v2.0.1 in every display/doc location, publish the release to GitHub, then execute a full multi-standard security and compliance audit organized under `docs/security-audit/`.

**Architecture:** Three sequential phases — (1) version bump across all files, (2) PR → merge → tag → release, (3) parallel subagent security audit covering OWASP Top 10, ISO 27001:2022, NIS2, ISO 22301, GDPR/RGPD, and SOC2-style controls. Audit output lands in `docs/security-audit/` as individual markdown reports plus a master index.

**Tech Stack:** Bash / git / GitHub CLI (`gh`), Next.js locale JSON files, Node.js package.json, Markdown documentation.

```bash

  --base main \

## Summary

- nginx 1.27 → 1.30 (stable, EOL open)
- New `GET /api/system-info` endpoint (admin only) with dynamic 5-column stack-versions table backed by endoflife.date (24h cache)
- Fixed retry race condition in system info panel
- Sticky `top-0 z-10` headers on all authenticated pages
- Node.js 20-alpine → 22-alpine base image; all frontend and backend npm packages upgraded to latest stable
- Architecture, user manual, and sysadmin manual updated for v2.0.1 stack

## Test plan

```

- [ ] **Step 2: Pull main locally**

```bash

```

- [ ] **Step 3: Create annotated tag**

```bash
git tag -a v2.0.1 -m "v2.0.1 — nginx 1.30, dynamic system info panel, sticky headers, stack upgrades"
```

- [ ] **Step 4: Push tag**

```bash
git push origin v2.0.1
```

- [ ] **Step 5: Create GitHub release (latest)**

```bash
gh release create v2.0.1 \
  --title "v2.0.1 — Stack Upgrade & Dynamic System Info" \
  --notes "$(cat <<'EOF'
## What's new in v2.0.1

### Features
- **Dynamic System Info Panel** (`GET /api/system-info`, admin only): 5-column table showing every stack component (OS, Node.js, PostgreSQL, nginx, Prisma, Next.js, etc.) with installed version, latest version from endoflife.date, EOL date, and status badge. 24-hour cache on EOL API calls.
- **Sticky Page Headers**: All authenticated-page header bars now use `sticky top-0 z-10` — they remain visible while scrolling through long lists.

### Upgrades
- **nginx 1.27 → 1.30** (stable branch, EOL open)
- **Node.js 20-alpine → 22-alpine** (LTS)
- All frontend and backend npm packages updated to latest stable versions
- Architecture, user manual, and sysadmin manual docs updated

### Bug Fixes
- Fixed retry race condition in system info panel on auto-refresh

### Breaking Changes
None. Fully backwards-compatible with v1.x data and configuration.

---
See [SYSADMIN_MANUAL.md](docs/SYSADMIN_MANUAL.md) for upgrade instructions.
EOF
)" \
  --latest
```

- [ ] **Step 6: Verify release**

```bash

```

### Task 8: Dispatch parallel audit subagents

**IMPORTANT:** Spawn the following 5 subagents **simultaneously** using the `superpowers:dispatching-parallel-agents` skill. Each subagent reads the codebase and writes its report to the designated file.

#### Subagent A — OWASP Top 10

File: `docs/security-audit/owasp-top10.md`

Audit prompt:
> Read `backend/src/index.ts`, `frontend/lib/apiFetch.ts`, `frontend/contexts/AuthContext.tsx`, `nginx/conf.d/frontend.conf`, and `docker-compose.prod.yml`. Produce a full OWASP Top 10 (2021 edition) audit for the CMDB Enterprise Platform v2.0.1. For each of the 10 categories (A01 Broken Access Control through A10 SSRF) assess: current controls in the codebase, gaps or risks found, severity (Critical/High/Medium/Low/Info), and concrete remediation recommendation. Use the vibesec-skill for methodology. Format as a markdown table per category plus detailed findings sections. Save to `docs/security-audit/owasp-top10.md`.

#### Subagent B — ISO 27001:2022

File: `docs/security-audit/iso27001.md`

Audit prompt:
> Read `backend/src/index.ts`, `backend/prisma/schema.prisma`, `SECURITY_AUDIT.md`, `docker-compose.prod.yml`, and `docs/SYSADMIN_MANUAL.md`. Produce an ISO/IEC 27001:2022 controls audit for CMDB Enterprise Platform v2.0.1. Cover Annex A controls relevant to the application: A.5 Org controls (policies, roles), A.6 People controls, A.7 Physical controls (container isolation), A.8 Technology controls (access, crypto, logging, ops security, supplier relations, incident, business continuity, compliance). For each relevant control: current state, evidence found in code/config, gap assessment, risk level (High/Medium/Low), and recommended remediation. Format as structured markdown with a summary compliance table. Save to `docs/security-audit/iso27001.md`.

#### Subagent C — NIS2 + ISO 22301

File: `docs/security-audit/nis2.md` and `docs/security-audit/iso22301.md`

Audit prompt:
> Read `backend/src/index.ts`, `docker-compose.prod.yml`, `docs/SYSADMIN_MANUAL.md`, and `SECURITY_AUDIT.md`. Produce TWO audit reports:
> 1. NIS2 Directive (EU 2022/2555) audit saved to `docs/security-audit/nis2.md`. Cover: risk management measures (Art. 21), incident handling, business continuity, supply chain security, network security, MFA/access control, cryptography, vulnerability management, reporting obligations. Assess compliance status per article/measure.
> 2. ISO 22301:2019 Business Continuity audit saved to `docs/security-audit/iso22301.md`. Cover: BIA (Business Impact Analysis) applicability, RTO/RPO considerations for the CMDB platform, backup and recovery procedures (DB dump scripts in sysadmin manual), disaster recovery runbooks, failover architecture gaps. Rate each area.

#### Subagent D — GDPR/RGPD

File: `docs/security-audit/gdpr.md`

Audit prompt:
> Read `backend/src/index.ts`, `backend/prisma/schema.prisma`, `docs/USER_MANUAL.md`, and `docs/SYSADMIN_MANUAL.md`. Produce a GDPR/RGPD compliance audit for CMDB Enterprise Platform v2.0.1. The platform stores: user accounts (email, hashed password, MFA secrets, SSO IDs), audit logs (user email + action), CI/asset data (company-internal, not personal), document metadata. Assess: lawful basis, data minimisation, storage limitation, data subject rights (access, erasure, portability), security of processing (encryption at rest/transit, access control, pseudonymisation), breach notification readiness, DPA requirements, retention policies. Rate compliance per GDPR article. Save to `docs/security-audit/gdpr.md`.

#### Subagent E — General Security Findings

File: `docs/security-audit/general-security.md`

Audit prompt:
> Read `backend/src/index.ts`, `nginx/conf.d/frontend.conf`, `docker-compose.prod.yml`, `backend/src/services/ldap.ts`, `backend/src/services/microsoftSso.ts`, and `backend/src/services/emailService.ts`. Use the `find-bugs` and `differential-review` skills. Produce a general security findings report for CMDB Enterprise Platform v2.0.1. Cover: (1) authentication & session management hardening (JWT, MFA bypass vectors, SSO nonce/state handling), (2) injection risks (SQL via Prisma raw, LDAP injection, path traversal in file uploads), (3) secrets management (env var exposure, JWT secret strength), (4) HTTP security headers (CSP, HSTS, X-Frame-Options in nginx config), (5) rate limiting and DoS exposure, (6) dependency CVE exposure (review package.json versions). For each finding include: CVSS score (estimated), affected code location (file:line), and remediation steps. Save to `docs/security-audit/general-security.md`.
